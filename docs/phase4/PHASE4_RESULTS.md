## Data integrity incident (documented, fixed)

The Oct-30 repair passes targeted calls that had already succeeded elsewhere
(find_invalid bug) using a repair template that does not include the original
candidates; those responses returned valid JSON with near-default `chosen`
fields. Fixes: (1) `find_invalid` now skips any call with a valid attempt
anywhere; (2) the loader's dedup prefers valid ORIGINAL attempts over repair
attempts and exposes `from_repair`; (3) all choice-based analyses exclude
repair-saved rows. Impact: phase 4 ~1% of rows; historical Qwen 6,406 rows
(13%) — but Qwen's headline E2 cells move ≤ .8pp (originals-only .384/.220 vs
published .386/.228), consistent with the report's existing strict-validity
sensitivity. Published conclusions unaffected.
